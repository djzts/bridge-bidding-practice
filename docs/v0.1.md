# 桥牌叫牌练习器 / Bridge Bidding Trainer

产品设计大纲 v0.1

本文记录前期产品设计与第一版范围，不涉及具体代码实现。

## 1. 产品定位

一个支持中英文的单人叫牌练习网站。用户选择或配置搭档体系，系统发牌并控制另外三家叫牌，帮助用户练习、理解和复盘叫牌。

基本原则：

- 部署在 GitHub Pages，核心功能全部在浏览器运行。
- 无需登录，暂不支持远程实时双人练习。
- 体系和练习记录保存在本地，支持文件导入、导出和牌局链接分享。
- 自动叫牌与解释使用同一套规则。
- 对尚未覆盖的叫牌局面明确提示，不编造体系解释。

## 2. 网站结构

| 页面 | 用途 |
|---|---|
| 开始练习 | 选择练习模式、体系和看牌方式 |
| 叫牌桌 | 看牌、叫牌、查看历史和提示 |
| 体系配置 | 管理基础体系、约定叫和具体参数 |
| 约定叫资料库 | 查阅约定含义、适用条件及例子 |
| 练习记录 | 查看历史牌局、收藏和错题 |

语言切换和设置入口在各页面保持可见。

## 3. 开始练习

### 3.1 练习模式

- **自由练习**：随机发牌，从开叫开始完成整轮叫牌。
- **主题训练**：选择想练习的内容，系统生成符合条件的牌局。主题包括开叫与应叫、无将体系、高花配合与邀局、约定叫专项、竞争性叫牌和满贯探索，按引擎实际支持范围逐步开放。
- **指定局面**：从预设的叫牌进程开始，直接练习某个决定。
- **错题重练**：重新练习曾经出现体系不符或主动标记为不理解的局面。

### 3.2 体系选择

- 我方体系：用户与自动搭档共同使用。
- 敌方体系：两名自动对手共同使用，可与我方不同。
- 第一版默认南家为用户，之后可扩展座位选择。

### 3.3 辅助设置

- 看牌方式：仅自己／自己与搭档／四手明牌／自定义。
- 自定义模式中，可分别显示或隐藏另外三家的手牌。
- HCP 显示或隐藏。
- 牌型统计显示或隐藏。
- 自动叫牌速度。
- 提示方式：关闭／主动查看／每次叫牌后反馈。
- 发牌人和局况：随机或指定。

## 4. 叫牌桌

### 4.1 桌面布局

| 区域 | 内容 |
|---|---|
| 顶部信息栏 | 当前模式、双方体系、发牌人、局况 |
| 中央牌桌 | 四家位置、可见手牌、当前行动者 |
| 叫牌历史 | W / N / E / S 四列排列 |
| 解释面板 | 叫品含义、提示、体系依据 |
| 底部操作区 | 用户手牌、HCP、叫牌器 |

手机端采用上下排列，解释面板可展开，自己的手牌和叫牌操作优先显示。

### 4.2 手牌显示

- 花色顺序：♠ ♥ ♣ ♦，黑红黑红。
- 每门按 A 至 2 排列。
- 牌面角标使用左上、右下布局，并保证重叠展示时可读。
- HCP 可隐藏。
- 可选显示各门张数与牌型。
- 隐藏的手牌显示统一牌背及张数。

### 4.3 叫牌器

- 1–7 阶的 ♣、♦、♥、♠、NT。
- Pass、Double、Redouble。
- 不合法叫品不可提交。
- 提交前显示选中状态，减少误触。
- 历史叫品可点开查看解释，手机端不依赖悬停操作。
- 支持提醒标记；第一版不模拟各赛制完整提醒程序。

### 4.4 练习操作

- 新的一副。
- 重新练习本副。
- 撤回自己的上一轮决定并重新尝试，同时回退后续自动叫牌。
- 查看提示。
- 显示／隐藏各家手牌。
- 收藏牌局。
- 结束并进入复盘。

使用提示、揭牌或撤回后，在记录中标记为“辅助练习”。

## 5. 体系配置

### 5.1 基础体系

从预设复制为自己的体系卡，再进行修改。配置内容包括：

- 开叫点力与牌型要求。
- 1NT、2NT 范围。
- 高花和低花开叫长度。
- 二阶开叫结构。
- 基本应叫与再叫原则。
- 逼叫、邀叫和止叫的定义。

每套预设标注版本和支持范围。第一套基础体系及具体覆盖进程尚待确定。

### 5.2 特殊叫品栏

支持搜索、分类筛选和多选启用。分类包括：

- 无将后的约定。
- 高花配合与加叫。
- 强开叫与后续。
- 弱二与阻击。
- 防守与争叫。
- 满贯问叫。

每项约定显示：

- 中英文名称。
- 简短用途。
- 适用叫牌进程。
- 可配置参数。
- 依赖、冲突和后续定义。
- 当前引擎是否支持执行。

“资料库中可查阅”与“引擎已支持使用”必须明确区分。资料库可以逐步扩展，不代表所有约定都已支持自动叫牌。

用户提供的约定清单参考：[Bridge Bum — Bridge Bidding Conventions](https://www.bridgebum.com/bridge_bidding_conventions.php)。后续整理时核对内容与使用方式，本文未逐项核验或收录。

### 5.3 配置校验

冲突检测依据具体叫牌进程、适用条件和叫品含义，不只比较约定名称。

| 类型 | 系统处理 |
|---|---|
| 直接冲突 | 指出具体进程及两种含义，要求解决后启用 |
| 条件不明确 | 要求补充适用条件，如是否受干扰、是否为已 Pass 的牌手 |
| 缺少必要后续 | 提示补全或使用预设后续 |
| 尚未支持 | 允许阅读，暂不能用于自动叫牌 |

冲突提示提供查看相关定义、调整条件和恢复预设的入口。

### 5.4 保存与分享

- 新建、复制、重命名、删除体系卡。
- 恢复预设。
- 导入、导出体系文件。
- 练习记录保存当时的体系版本，后续修改不改变旧牌局的解释依据。

## 6. 自动叫牌与解释

### 6.1 决策依据

第一版采用浏览器内的规则驱动叫牌引擎，不依赖在线大语言模型。每个自动牌手只读取：

- 自己的手牌。
- 公开叫牌历史。
- 发牌人、位置和局况。
- 自己所属搭档的体系及对手公开的约定信息。

界面的揭牌设置不改变自动牌手的信息权限。

### 6.2 两层解释

**公开含义：练习中可查看。** 说明这个叫品承诺的点力、牌型、逼叫性质和适用约定。

**本手理由：默认复盘时查看。** 说明实际手牌如何满足条件，以及为什么选择这一叫品。

两者分开控制，避免用户查看公开含义时意外得知隐藏手牌。搭档与敌方的解释可分别显示或隐藏。提前查看本手理由时，标记为辅助练习。

解释区分体系规定与牌手判断，不把每个决定都描述为唯一答案。中英文解释由相同的规则结果生成。

### 6.3 超出支持范围

- 明确指出缺少哪类规则。
- 不把临时选择说成体系规定。
- 允许结束复盘或重新发牌。

第一版只对已声明支持的练习范围提供可靠自动叫牌。

## 7. 结束与复盘

叫牌结束后显示：

- 最终定约、庄家和局况，或全 Pass。
- 完整叫牌历史。
- 四家手牌。
- 每个叫品的含义及实际选择理由。
- 用户决定中需要关注的地方。
- 已定义的合理替代叫品及取舍。

| 反馈类型 | 含义 |
|---|---|
| 符合体系 | 手牌与叫品表达一致 |
| 合理选择 | 存在判断空间 |
| 体系不符 | 点力、牌型或逼叫含义不匹配 |
| 暂无法评价 | 当前规则不足以作出可靠判断 |

第一版不以最终定约结果作为唯一评分，也不承诺每个局面都有唯一最佳答案。重点反馈用户表达了什么、搭档会如何理解，以及是否与实际手牌一致。

复盘后可以收藏、加入错题、重练或分享牌局。

## 8. 练习记录与本地数据

保存内容：

- 用户设置和语言。
- 体系卡及版本。
- 牌局、叫牌历史。
- 提示、揭牌与撤回使用情况。
- 收藏、错题和简短笔记。

提供自动本地保存、保存状态、全量备份与恢复、单副牌导出和牌局分享链接。

本地保存不会自动跨设备或浏览器同步；清除网站数据可能丢失记录，因此提供文件备份入口。

分享牌局时说明链接包含可还原牌局的信息，适合练习交流。手牌隐藏属于界面控制；全部牌局数据在本机，不用于提供比赛防作弊保障。

## 9. 中英文设计

- 所有界面、规则解释和错误提示支持中英文。
- 约定名称可同时显示英文，便于检索。
- 提供统一术语表。
- 切换语言保留当前牌局和设置。
- 体系、约定和规则使用固定内部标识，翻译不会改变其含义。

## 10. 第一版范围

核心闭环：

> 选体系 → 选训练 → 发牌 → 四家叫牌 → 查看解释 → 复盘 → 保存或重练。

第一版包含：

- 一套基础体系和少量完整支持的约定。
- 自由练习及几个主题训练。
- 四家手牌可见性控制。
- 叫牌器、历史、可隐藏 HCP。
- 自动叫牌与中英文解释。
- 基础复盘。
- 本地保存、文件导入导出及牌局链接分享。
- GitHub Pages 部署。

后续扩展：更多体系与约定、更多专项训练、指定局面编辑和更丰富的学习统计。

暂不纳入第一版：账号、跨设备自动同步、远程实时练习、完整打牌阶段，以及覆盖所有约定的通用叫牌引擎。
